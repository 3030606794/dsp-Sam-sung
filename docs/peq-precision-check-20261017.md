# PEQ 精度、频响与高采样率专项检查（2026-10-17）

## 模型与通信

- Q 存储、驱动合法范围为 0.0001～30000，保存值使用完整 `Double`。独立的 Q 步长下限为 0.0001；BW 步长为 0.0001～1，默认 0.01。
- 原二进制 schema 1 的 `Q × 1000` 会吞掉 0.0001 微调。中间评估的 float32 在 Q 接近 30000 时也只有约 0.001953 的分辨率，无法满足高端精调，最终没有采用该方案。
- 最终 SET 1250 使用 **二进制 schema 3**：头部仍为 `[schema, enabled, count]`，每段为 `[type, bandEnabled, frequency_mHz, gain_mdB, Q_double_low32, Q_double_high32]`。Q 的两个 int32 仅承载 IEEE754 Double 位模式，不做定点整数四舍五入。130 段为 3132 字节；驱动兼容的 170 段上限为 4092 字节。
- 频率为 1～768000 Hz，仍按毫赫兹传输；此上界乘 1000 不溢出 int32。超过实际处理 Nyquist 的滤波段由真实处理规则旁路，不移动用户保存的频率。
- 新驱动扩展能力位 8 用于确认此精度协议。旧 schema 1 / 2 的兼容解码与数学行为由驱动保留，新 APK 在不支持该能力时不向旧驱动发送 schema 3。

## Q 与 BW 的固定参考换算

最终 UI 采用与中心频率、处理采样率无关的参考八度宽度：

```text
BW = 2 × asinh(1 / (2Q)) / ln(2)
Q  = 1 / (2 × sinh(BW × ln(2) / 2))
```

BW 的全局范围固定为 **0.0001～26.5754247879528 oct**，移动频率不改变 BW 值或滑杆位置。BW 编辑不受用户单独设置的 Q 滑杆显示上限限制。BW 下限 0.0001 对应 Q 约 **14426.950406001522**；显式 Q 编辑遵守此 BW 下限及用户 Q 显示范围。读取旧保存值时保留到 Q 30000，不擅自裁剪已有滤波参数。

显示标签使用三位十进制 HALF_UP；编辑框保留完整十进制值，Q=0.0001 不显示成编辑值 0.000。三位显示不会回写到模型。加减采用十进制运算，避免反复加 0.0001 的二进制累积误差；端点仅容忍浮点运算的少量 ULP，不用固定宽阈值吞掉细调。

本地 JSON 升为 schema 3，保存独立 BW 步长及图纸范围。读取旧 schema 1 / 2 时仅将旧全量程 `qRange=100` 迁移为 30000，旧自定义范围保持；新 schema 3 显式设置的 100 也保持。旧 schema 1 中四种原本无效的增益仍按原迁移规则置零。

## 真实滤波数学与图纸

- 七种类型均由真实传递函数计算。schema 3 的峰值滤波加入与驱动一致的裙边补偿：`t=clamp(log10(Q),0,1)`、`weight=t²(3−2t)`、`effectiveQ=Q×10^(abs(gain)×weight/40)`；Q≤1 的宽峰不补偿，正负增益使用相同系数，保持互逆。
- 其余六类继续使用对应 RBJ 定义；通道、增益与频率均按实际下发值计算。没有用矩形或手绘曲线代替滤波响应。
- 极窄峰使用真实双线性频率映射，在中心、裙边及更窄的极值宽度上加密采样。预览 Worker 接收实际处理采样率并重新建立对应系数，避免固定 48 kHz 图纸。
- 图纸范围作为显示配置单独保存，支持 1～200 Hz 局部缩放；不写入任何 DSP 参数词。UI50 新建配置的首选上限为 768000 Hz，但实际画布直接截断为 `min(首选上限, fs/2)`，不保留超限灰区。已有明确保存的 20000 Hz 等缩放偏好保持。
- 极高 Q / 高增益的稳态建立可能很慢；稳定系数和解析稳态曲线不代表短时播放已经达到完整中心增益。

## 采样率与原生修复

- James 主引擎高于 48 kHz 时原本会内部转回 44.1 / 48 kHz；已让 44.1～768 kHz 直接使用 host rate。低于 44.1 kHz 的历史上采样兼容路径保留。各专业处理模块的相关 rate 入口、APK 健康与 IR 状态验证同步扩展。
- 实际 Fs 切换时刷新已启用处理器，并按保存的释放时间重算限幅器系数。专项定位的任意响应均衡器、立体声增强重复加锁已拆分成持锁内部入口，保留正常外部加锁包装。
- 768 kHz 下 200 ms 卷积延时为 153600 样本，500 μs 耳机馈送为 384 样本，相关固定环形缓冲已放大。休眠后的 retained delay / CRC 状态也接受合法高率样本数。
- 高采样率 DDC 从 48 kHz 原系数作逆 BLT 再映射，保持原文件 SHA / CRC；44.1 / 48 kHz 原系数不变。DDC 的 James 入口同时按专业工作核可用状态启用，不再因 legacy SOS 指针为空误关。

基础双二阶公式参考 [W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/)。本版峰值裙边补偿为上述明确列出的扩展；图纸按同一真实函数绘制。系统效果与路由边界参考 [Android Audio effects](https://source.android.com/docs/core/audio/audio-effects) 和 [Audio HAL](https://source.android.com/docs/core/audio/implement)。

## UI50 实际采样率与频率控件专项

- 频段频率滑杆、加减和手动输入的范围统一为 **1～实际 fs/2 Hz**，与图纸缩放独立。48 kHz 为 24000 Hz，384 kHz 为 192000 Hz，768 kHz 为 384000 Hz；不再减 1 Hz 或向下取整。
- 仅同一效果会话的处理帧变化确认放宽采样率。休眠、不可读及刚替换会话保留最后安全采样率，首次缺省 48 kHz；合法的较低当前配置立即收紧。多个启用会话取最保守上限，不使用 USB 宣告采样率。
- 采样率变化不会重写保存的频段频率或 Q/BW。图纸保留高率首选上限，低率时显示实际上限，升率后恢复；设置弹窗未主动修改最高频率而确认其他选项，不会把首选 768000 Hz 永久改为 24000 Hz。
- 降率后的超限频段保留原保存值，仅将滑块视觉夹在端点；用户明确触摸此端点时立即提交当前允许频率，使数值与滑块一致。此处理只作用于可编辑的超限频率，合法精细值、锁定频率及 Q/BW 不受影响。
- 已打开的设置和精调弹窗同步更新滑杆范围、文字与手输校验，确认时再次按当前上限验证。最高频率标签和无障碍描述也显示实际允许范围。
- 精确 fs/2 中心频率仍原样保存和显示，实际系数与原生端一致以 **fs/2−0.001 Hz** 计算左极限；只有中心大于 fs/2 才旁路。预览在真实系数中心密采样，没有以整段旁路伪造端点曲线。

本机纯 Kotlin 精选原六类及新增 `PeqFrequencyLimitsTest` 共 **64/64 通过**。新增 6 项验证精确/非整数端点、48/384/768 kHz 截断与恢复、静态配置不冒充实际处理、切低率立即收紧、固定 BW 与保存值不变、七类 Nyquist 左极限与真实曲线。最终 Android 定向验证中，`PeqNyquistUiTest` 3 项及 `PeqPrecisionUiTest` 6 项也全部通过；降采样率后的超限频率只在用户再次触摸频率滑杆时提交实际端点。APK 与驱动成品、85 项总验证及硬件测试边界见 [UI50 最终检查](usb-follow-nyquist-check-20261017.md)。
