# DSP Fusion 0.1.0-alpha1：与旧版的兼容性

这是一套可自行安装测试的初版：一个 DSP Fusion APK、一个 Magisk 模块、一个系统音效库和一个公开音效实例。库内依次运行 JamesDSP → 十项听感调节 → ViPER RE。没有安装到你的手机进行实测。

## 安装与回退

1. 在旧 JamesDSP/ViperFX 中导出想保留的预设，保留原 APK 和模块安装包。卸载应用会删除它的私有设置。
2. 在 Magisk 禁用 JamesDSP Manager (`ainur_jamesdsp`)、ViPER4Android RE Fork、ViPER AIDL，以及 Audio Modification Library Ryuki (`aml`)。AIDL 原本已禁用，保持禁用。新模块自行生成音效配置，不依赖 AML；让旧 AML 继续挂载旧配置可能覆盖新模块。
3. 刷入 `DSP-Fusion-Driver-0.1.0-alpha1.zip`，重启。安装 `DSP-Fusion-0.1.0-alpha1.apk`，按应用提示启用音效。旧应用可以按你的计划卸载。首次测试从较低音量和单项效果开始。
4. 如需回退，禁用 DSP Fusion 模块、重新启用原 JamesDSP/Viper/AML 模块，再重启并安装原 APK、导入原预设。无需删除音乐文件或恢复系统分区。

安装器只修改模块目录里的配置副本，通过 Magisk 挂载；不直接写系统分区。检测到上述旧模块仍启用时会停止安装并明确显示名称。

## 版本和功能差异

| 项目 | 初版行为 |
|---|---|
| 应用包名/签名 | 新包名 `com.dspfusion.android`，独立持久签名，不能当作官方 `james.dsp` 的覆盖升级。后续本项目 APK 可沿用同一签名升级。 |
| 驱动 | 新模块 ID `dsp_fusion`，库 `libdspfusion.so`，独立 UUID。旧 JamesDSP 或 Viper 单独驱动不满足新应用协议。 |
| 平台 | Android 8.0/API26 及以上，ARM64/ARMv7。目标首先是当前三星 Android15 的传统全局音效路径；不同 AIDL/HAL、直通或播放器独占 USB 路径仍需要你实测。 |
| JamesDSP | 保留 1.6.14 原有 EQ、动态低音、压扩器、混响预设、声场、交叉馈送、VDC、卷积与 LiveProg。 |
| Viper | 接入当前 RE 0.6.3 已实现的频谱扩展、十段EQ、环绕声场、差分环绕、混响、动态系统、电子管、低音、清晰度、听觉保护、AnalogX、扬声器优化、输出音量/平衡/限制。 |
| DDC/卷积 | 使用 JamesDSP 原有文件导入和处理入口共享。不是两份独立的 VDC/卷积槽。 |
| 上游未实现项 | RE 源码中的独立 AGC、部分 FET 压缩器和耳机 VHE 路径不完整，初版不提供无效开关。截图中的环绕声场、差分环绕和混响与 VHE 是不同功能。 |
| “FIR EQ”名称 | Viper 原应用叫 FIR，当前 RE 引擎实际使用十段 IIRFilter；新界面按真实实现标注。 |
| 海贝十项 | 提供总温度、低音下潜、低音弹性、厚度、人声、女毒、两段齿音、乐器瞬态、空气声及±20/40/100范围。采用独立滤波/动态模型近似听感，不能承诺相同档位等于海贝原版声音。详细频率和映射见 `native/tone/README.md`。 |
| 旧预设 | James 导出预设沿用原格式；载入不含新参数的旧预设时重置新组以避免残留叠加。Viper和海贝私有预设不自动迁移，需按原数值手动设定；海贝相同整数只保证档位相同，不保证算法相同。 |
| 更新 | 使用本仓库 Releases 手动下载，不从原 JamesDSP 更新服务器安装应用。私有仓库需要登录对应 GitHub 账号。 |

## 听感可能变化的原因

处理顺序固定，避免两个应用争用控制权，但跨系统原本的两个效果顺序并非所有路径都保证一致。James 内部采样转换、Viper 的固定样本混响延迟、Viper 末级限制器，以及新听感调节的电平余量，都会影响最终输出。Viper 内部仍保留其原来的限幅行为，两个引擎同时开时应避免不必要的重复提升。

新组默认关闭，调节值为中性。建议先检查 James 单独工作，再启用 Viper 单项，最后加入听感面板。原版扬声器混响对照值可手动设置为：新版房间大小60、宽度0、阻尼0、湿声36、干声50（旧版房间档位6对应新版60）。干声50对应原声单位增益，100并不是“原声不变”。

初版交付前执行源码构建、协议/音频离线测试、APK签名和模块结构检查。真实系统路由、长时间播放、功耗和个人听感由后续实机测试确认；构建成功不等于所有手机已验证。
