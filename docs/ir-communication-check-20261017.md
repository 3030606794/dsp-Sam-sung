# 脉冲响应通信专项检查（2026-10-17）

本记录区分代码核对、本机专项测试与真机验证。未执行无关 UI 全量回归。

## 确切问题与修复

只读检查现有设备日志发现，失败工作核为 **18824 帧、双声道，CRC 345625875**；该标识对应此次输入处理得到的全零工作核。驱动在裁去末尾零系数后把长度降为 0，后续创建卷积计划拒绝零长度，错误被归到 `-ENOMEM`。这是全零核的边界处理错误，**并非 18824 帧超过传输容量**。修复保留全零 IR 的有效零响应语义，避免由裁尾触发错误的内存不足状态。

APK 还存在确认与恢复方面的问题：把提交后的工作核确认和实时处理就绪混在一起，失败时直接提示并旁路；无活动音频流时也会走此分支。修复后的确认使用稳定序列的独立核元数据，核已装载且 CRC、帧数、通道匹配即可确认，允许尚未确定实时采样率的 `rate = 0`，不要求实时 `ready` 标志。采样率已知时必须与目标匹配。

恢复策略限定在 IR 模块：初次下发后最多进行 3 次静默重试；无音频流时耗尽预算后进入待激活状态，不能转为致命失败。音频唤醒重新获得完整重试预算；新目标取消旧预算；多次真正失败的提示每轮只发一次。其他音效模块继续使用原参数通道。

## 已核对的下行协议

| 项目 | APK 下发格式 | 驱动接收约定 | 结果 |
| --- | --- | --- | --- |
| 参数头 | Android AudioEffect；32 位参数 ID | `effect_param_t.psize = 4` | 一致 |
| IR 准备 `9999` | 4 个原生字节序 int32：总样本数、通道数、增益 0、块数 | 16 字节；通道数为 1 / 2 / 4；总样本数按通道整除 | 一致 |
| IR 数据 `12000` | 每块 4096 个 float，尾块补零 | 每块 16384 字节，拒绝非有限样本及超出准备块数的数据 | 一致 |
| IR 提交 `10004` | int16，2 字节；全部数据块成功后调用 | 必须已接收全部准备块 | 一致 |
| IR 缓存 CRC `25003` | int32 | 4 字节 | 一致；CRC 本身还须结合工作核状态判断 |

IR 传输分配上限为 32 MiB，APK 和驱动均按“补齐的 4096-float 块”计算。总样本数已经包含通道，不能再乘通道数。16383 帧双声道原始数据为 131064 字节（8 块），18824 帧为 150592 字节（10 块），均远低于上限。因此仅这些帧数不能证明存在容量不足。

IR 的历史 CRC 是针对 float 原始位模式的旧 JamesDSP 算法，不是普通字节流 CRC32。预处理测试使用固定历史向量检查了兼容性；窗口、归一化、矩阵和分数延时处理均使用工作副本，测试检查了源数据不被改写。

主要依据：`interop/ImpulseResponseTransfer.kt`、`utils/extensions/AudioEffectExtensions.kt`、驱动 `native/fusion/FusionEffect.cpp` 的 `validateJames` / `commandInternal`，以及 `jamesdsp.c` 的参数处理分支。

## 其他参数通道抽检

- 总开关仍由 `AudioEffect.setEnabled` 下发，对应驱动 `EFFECT_CMD_ENABLE` / `EFFECT_CMD_DISABLE`。James / ViPER 阶段启用包分别为 `131072` / `131073`，均为 int32 布尔值。
- 阈值、释放、后增益使用 `1500`，按此顺序发送 3 个原生字节序 float，共 12 字节；驱动按相同顺序读取。平衡为 `131074`，单个 int32，范围 −100～100。
- DDC 为 `8888`（int32 块数、256）、`12001`（固定 256 字节原始文件块）、`10009`（2 字节提交）、`25001`（4 字节 CRC）。完整传输和文件身份确认在激活之前，失败保留前次有效校正。
- 专业页顶部开关仍调用原 `SwitchPreferenceGroup.callChangeListener` / `setValue`；输出滑杆、加减、手动输入、双击复位仍统一保存原偏好键并广播原更新事件。float 项保存 float，平衡保存 int。
- 最近修改的低频、高频、交叉馈送、立体声、混响、音色等专业页仍经原 Controller / 参数模型进入统一发送函数。抽检的专业数组使用 int32；保留的 James 2 字节开关与 ViPER 4 字节开关继续分别编码，未发现由 UI 移位造成的接口错接。
